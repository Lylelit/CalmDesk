# 📅 Месячный планировщик задач

Визуальный планировщик задач на месяц с почасовым распределением.

![React](https://img.shields.io/badge/React-18-blue)
![Vite](https://img.shields.io/badge/Vite-6-purple)
![Tailwind](https://img.shields.io/badge/Tailwind-4-cyan)

## ✨ Возможности

- **Доска на месяц** — недели × 5 рабочих дней
- **8 часов в каждом дне** — видно, сколько свободно
- **Drag & Drop** — перетаскивайте задачи между днями
- **Разбивка задач** — разделяйте блоки на части
- **Цветовая кодировка** — каждая задача своего цвета
- **Сохранение** — данные хранятся в localStorage

## 🚀 Быстрый старт

```bash
# Установка зависимостей
npm install

# Запуск dev-сервера
npm run dev

# Сборка для продакшена
npm run build
```

## 🛠 Стек

- React 18
- TypeScript
- Vite
- Tailwind CSS 4

## 📋 Как пользоваться

1. Создайте задачу в боковой панели (укажите название, часы, цвет)
2. Перетащите задачу на любой день — появится выбор часов
3. Перетаскивайте блоки между днями для перераспределения
4. Разбивайте задачу на части (✂️) или убирайте из дня (✕)

## 📄 Лицензия

Использование, копирование и распространение данного программного обеспечения без письменного согласия автора строго запрещено

## Supabase (переезд на облачное хранилище)

Код полностью готов к работе с Supabase и автоматически переключается:
- **`.env.local` не заполнен** → приложение работает как раньше, на localStorage.
- **`.env.local` заполнен** → авторизация через Supabase Auth, данные в Supabase Postgres.

### Пошаговая настройка
1. Зарегистрируйтесь на https://supabase.com и создайте проект (бесплатный ок).
2. В проекте: **SQL Editor → New query** → вставьте содержимое `supabase/schema.sql` → **Run**.
3. **Project Settings → API**: скопируйте `Project URL` и `anon public` key.
4. В корне проекта создайте файл `.env.local` (по образцу `.env.example`):
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```
5. Перезапустите `npm run dev`. Экран входа станет email+парольным; при первом
   входе старые локальные данные пользователя перенесутся в облако автоматически.

### Роли и команда
- Первый зарегистрированный пользователь получает роль `manager`, остальные — `employee`
  (триггер в схеме). Менять роли: SQL Editor →
  `update profiles set role='manager' where email='...';`
- Руководитель видит панель «Команда»: добавляет сотрудника по email,
  смотрит его доску, создаёт ему задачи и скачивает Excel-статистику.
- Доступ к данным разграничен политиками RLS: сотрудник не видит чужие доски.
