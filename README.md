# 📅 Месячный планировщик задач

Визуальный планировщик задач на месяц с почасовым распределением.

![React](https://img.shields.io/badge/React-18-blue)
![Vite](https://img.shields.io/badge/Vite-6-purple)
![Tailwind](https://img.shields.io/badge/Tailwind-4-cyan)

## ✨ Возможности

- **Доска на месяц** — недели × 5 рабочих дней
- **8 часов в каждом дне** — видно, сколько свободно
- **Drag & Drop** — перетаскивайте задачи между днями
- **Разбивка задач** — разделяйте блоки на части
- **Цветовая кодировка** — каждая задача своего цвета
- **Сохранение** — данные хранятся в localStorage

## 🚀 Быстрый старт

```bash
# Установка зависимостей
npm install

# Запуск dev-сервера
npm run dev

# Сборка для продакшена
npm run build
```

## 🛠 Стек

- React 18
- TypeScript
- Vite
- Tailwind CSS 4

## 📋 Как пользоваться

1. Создайте задачу в боковой панели (укажите название, часы, цвет)
2. Перетащите задачу на любой день — появится выбор часов
3. Перетаскивайте блоки между днями для перераспределения
4. Разбивайте задачу на части (✂️) или убирайте из дня (✕)

## 📄 Лицензия

Использование, копирование и распространение данного программного обеспечения без письменного согласия автора строго запрещено

## Supabase (переезд на облачное хранилище)

Код полностью готов к работе с Supabase и автоматически переключается:
- **`.env.local` не заполнен** → приложение работает как раньше, на localStorage.
- **`.env.local` заполнен** → авторизация через Supabase Auth, данные в Supabase Postgres.

### Пошаговая настройка
1. Зарегистрируйтесь на https://supabase.com и создайте проект (бесплатный ок).
2. В проекте: **SQL Editor → New query** → вставьте содержимое `supabase/schema.sql` → **Run**.
3. **Project Settings → API**: скопируйте `Project URL` и `anon public` key.
4. В корне проекта создайте файл `.env.local` (по образцу `.env.example`):
   ```
   NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=eyJ...
   ```
5. Перезапустите `npm run dev`. Экран входа станет email+парольным; при первом
   входе старые локальные данные пользователя перенесутся в облако автоматически.

### Что хранится в Supabase
После применения схемы в облаке живут **все данные доски** пользователя:
- `tasks` — задачи (название, часы, статус, описание, ссылка, цвета);
- `assignments` — назначения задач на дни ленты (часы, порядок);
- `day_statuses` — статусы дней (отпуск / выходной / короткий день);
- `profiles`, `team_memberships` — аккаунты, роли и команды.

Все таблицы привязаны к владельцу (`owner_id = auth.uid()`) и защищены RLS,
поэтому, войдя в свой аккаунт с любого устройства и браузера, пользователь
видит свой планер с теми же задачами. При первом входе в облачном режиме
локальные данные (localStorage) автоматически переносятся в Supabase один раз.

### Как проверить, что всё работает
1. Откройте сайт → F12 → вкладка **Console**. Фразы «Supabase не настроен»
   быть не должно — если есть, значит сборщик GitHub Pages не получил ключи
   (см. раздел про GitHub Pages ниже).
2. **Auth → Users** в Supabase Dashboard: после регистрации там должен появиться
   пользователь; в таблице `profiles` — строка с его `id` и ролью.
3. Создайте задачу, обновите страницу / откройте сайт в другом браузере —
   задача должна остаться (в SQL Editor: `select * from tasks;`).
4. Если вход проходит, но доска пустая или роль не определяется — скорее всего
   `schema.sql` не применён или применён частично. Просто выполните файл ещё раз
   (он идемпотентен), затем выйдите и войдите снова — функция
   `ensure_my_profile()` восстановит отсутствующий профиль автоматически.
5. Ошибка вида **403 / `permission denied for table profiles|tasks|assignments|day_statuses`**
   означает, что в проекте Supabase отключены прямые привилегии на таблицы
   (так настроены все новые проекты после ~мая 2025: политика RLS есть, но
   роли `anon`/`authenticated` нет права `SELECT`). Решение: выполнить в
   SQL Editor обновлённый `supabase/schema.sql` целиком — в него добавлены
   `GRANT`-инструкции; либо быстро проверить тем же запросом:
   ```sql
   grant usage on schema public to anon, authenticated;
   grant select, insert, update, delete on all tables in schema public to anon, authenticated;
   ```
   После этого перезагрузить страницу сайта — ошибки 403 исчезнут.
6. Ошибка вида **400 Bad Request при POST `/rest/v1/tasks?columns="id","owner_id",...`**
   почти всегда означает несовпадение типов: колонка `id` в таблице имеет тип
   `text`, а приложение присылает UUID-строку (или наоборот), либо отсутствует
   обязательная колонка `owner_id`. В `supabase/schema.sql` добавлен блок
   «Самовосстановление схемы» (раздел 3.1): повторно выполните весь файл в SQL
   Editor — он безопасно добавит недостающие `owner_id` и приведёт текстовые
   id к типу uuid. После этого обновите сайт.

### Роли и команда
- Первый зарегистрированный пользователь получает роль `manager`, остальные — `employee`
  (триггер в схеме). Менять роли: SQL Editor →
  `update profiles set role='manager' where email='...';`
- Руководитель видит панель «Команда»: добавляет сотрудника по email,
  смотрит его доску, создаёт ему задачи и скачивает Excel-статистику.
- Доступ к данным разграничен политиками RLS: сотрудник не видит чужие доски.

## Публикация для других пользователей (GitHub Pages)

В репозитории уже лежит workflow `.github/workflows/deploy.yml`: при каждом пуше
в ветку `main` сайт собирается и публикуется на GitHub Pages по адресу
`https://<ваш-логин>.github.io/<имя-репозитория>/...`
(точный адрес публикуется в логе деплоя и в Settings → Pages).

**Обязательно перед первым деплоем:** так как `.env.local` не попадает в git,
нужно передать ключи Supabase сборщику на GitHub:
1. Репозиторий → **Settings → Secrets and variables → Actions → Variables → New repository variable**:
   - Работают оба набора имён: `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`
     и `NEXT_PUBLIC_SUPABASE_URL`/`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
     (первые — рекомендуемые для Vite).
2. Также в **Settings → Pages** источник (Build and deployment) должен быть **GitHub Actions**.
3. Сделайте push в `main` и дождите зелёного галочку у коммита — адрес появится во вкладке Actions → Deploy.

Если переменные не задать, публичная версия не упадёт в белый экран (защита в
`supabaseClient.ts`), но будет работать на localStorage каждого браузера,
то есть общий облачный доступ между пользователями не сработает.
